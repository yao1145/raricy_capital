# 控制用户：机构本金与手续费划转

日期：2026-10-04。适用于 capital1 与 capital2，同一个控制用户分别持有两只基金的份额。

## 资金规则

| 资金来源 | 记账与去向 |
| --- | --- |
| 控制用户转入任一基金账户 | 全额登记为机构本金，申购费为 0；本金留在该基金交易账户 |
| 其他用户申购 | 净本金留在基金，另收净本金的 5% 申购费 |
| 其他用户的申购费 | 份额发行成功后，排队转到控制用户；发行前仍是可退的预收费用 |
| 紧急赎回费 | 保持原规则，留在原基金，不转给控制用户 |
| 分红与赎回 | 保持原规则，机构按自有份额参与；没有机构优先赎回权限 |

例如：其他用户净申购 1000，实际支付 1050。发行后 1000 留在基金、50 划转控制用户；
控制用户转入 1000，1000 全部作为机构本金，无额外费用。

控制用户可以直接转账，无需先建订单、填写指定备注或遵守二维码的 180 秒期限。
该直接入金不受新申请窗口限制；使用 `/subscription` 命令创建新订单仍限每月 1 日至 7 日 18:00。
系统依据站点核实的付款人 ID、到账时间与唯一流水登记，重复发现同一流水不会再次入账。
每笔转入都会有独立的机构本金订单与通知；若符合已有未付款订单的付款信息，复用该订单。

**免手续费不等于立即取得份额。** 机构本金沿用结算批次确认流程（次月 7 日 20:00 统一估值）；每月 7 日 18:00（北京时间）
之后到账归下月。确认前列为待确认本金，不进入旧份额的净资产，也不能用于开仓；确认后
按适用净值发行控制用户份额并记录资本流。追加本金不解除永久停机。
控制用户仍通过普通撤回、赎回与分红流程操作自己的订单和份额。

## 配置与权限

```yaml
# 两只基金共用；填写实际站点用户 ID，不能填用户名、密码或令牌。
control_user_id: "your-site-user-id"
live: false
```

可用环境变量 `FUNDS_CONTROL_USER_ID`；非空 YAML 优先，YAML 留空时读取环境变量。
两者均为空时关闭控制用户特权与新增手续费划转。ID 只接受 1～128 个字母、数字或
`_ . : -` 字符，非法类型或空格报 `invalid_control_user`。

控制用户必须与两个交易账号分别不同；启动时检查已登记账号，登录时再核实站点返回的
账号 ID，冲突报 `control_user_cannot_be_fund_account`。不通过改用户名绕过身份检查。
控制用户身份与运营台管理令牌分别配置；设置 ID 本身不授权访问运营台。
实际用户 ID 仅放部署环境或 Git 忽略的 `config.local.*`，公开示例使用占位符。

## 私聊 `/check`

控制用户私聊任一基金 `/check`，收到两只基金的资金总览：

- 状态、净值、总份额、控制用户份额及估值；
- 账户钱包、持仓净价值、基金净资产、可用现金；
- 控制用户累计登记本金、全基金初始登记本金、待确认本金；
- 预收及历史未转出费用、应付款、未认领款；
- 已实现交易利润、累计净资本流入；
- 机构手续费累计已转出、待转出及其中结果未知的金额；
- 各基金最近估值时间。

查询按最近本地账簿快照返回。已转出手续费是累计金额，不是控制用户外部钱包的实时余额；
累计登记本金也不是当前可赎回金额。待转出金额包含结果未知的部分，不能把两项相加。
普通用户仍只看到自己在所私聊基金的持仓；公开频道不执行命令，显示名不能取得特权。

## 付款与账务约束

1. 发行事务把对应申购费从预收费用改记为机构应付款，不重复影响基金净值。
2. 每笔费用对应一个持久付款意图，业务键由基金与申购订单派生；收款人、金额、备注和
   幂等键固定。改变控制用户配置不改写已经创建的付款意图。
3. 实付前读取新余额，保护待确认本金、未认领款和其他应付款；现金不足保持等待。
4. 超时、断网或回执不确定时先核对完整出账流水。只有唯一匹配收款人、金额、备注及
   上游流水身份时确认已付；只有完整核对证明未付，才可使用原幂等键重试。
5. 确认付款使用核实的绝对钱包余额，并清除相应负债，避免轮询已扣余额后再次扣账。
6. `live: false` 禁止外部转账与私聊，不主动把历史费用转成新增付款队列。

未发行申购撤回仍退还本金与预收申购费。机构费用不会提前转走导致退款缺钱。

## 升级与历史账目

- 配置启用后，live 工作循环会扫描已发行、尚未排队且仍记在账簿中的其他用户申购费，
  一次性建立划转队列。未发行订单不参与；已经有付款意图的订单不重复排队。
- 不追溯修改历史本金归属、份额或已处理的未认领款。历史控制用户付款若已成为未认领款，
  使用[人工核对路径](../usage/UNCLAIMED_REVIEW.md)处理，不自动重记。
- 若历史费用曾在程序之外手工转走却未入账，启用前应先核对这部分账目，避免重复支付。
- 暂时关闭或更换控制用户不会取消已有机构费用负债；原收款人与原幂等键保留。
- 本地回归不代表真实站点验收；上线需升级整包、写入目标配置并重启唯一服务进程。
  部署步骤见[DEPLOYMENT.md](../usage/DEPLOYMENT.md)。

接口：`FundLedger.is_control_user`、`control_finances`、`queue_institution_fees`；
付款入口：`PaymentsWorker.drain_institution_fees`。金额沿用整数 1e-4，份额沿用整数 1e-8。
针对性测试见 `tests/test_control_user.py`。
